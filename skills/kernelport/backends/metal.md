# Porting CUDA to Metal (MLX custom kernels)

A metal port is the **body** of a Metal compute kernel. MLX (`mx.fast.metal_kernel`)
writes the signature, compiles it, and launches it on the Apple GPU. A CUDA thread
block is a Metal **threadgroup**, `__shared__` is `threadgroup`, `__syncthreads()` is
`threadgroup_barrier(mem_flags::mem_threadgroup)`.

Verification needs an Apple Silicon Mac with MLX. On other machines `verify_port`
returns UNVERIFIED. **Status: the runner and the zoo ports are written but have not yet
been verified on a Mac.** The first `kernelport zoo --backend metal` on a Mac is
the real test.

## Port file format

```python
"""Metal (MLX) port of saxpy: y = a * x + y."""

SOURCE = """
    uint i = thread_position_in_grid.x;
    if (i < uint(n[0])) {
        y_out[i] = static_cast<T>(a[0] * static_cast<float>(x[i]) + static_cast<float>(y[i]));
    }
"""
THREADGROUP = (256, 1, 1)


def grid(n):
    return (n, 1, 1)          # TOTAL threads, not threadgroups
```

- **`grid()` returns total threads per dimension** (Metal `dispatchThreads`), unlike
  CUDA's block counts. One threadgroup per row of 256 threads: `(rows * 256, 1, 1)`.
- Names (launch.json order), generated by MLX:
  - inputs: every `input` and `inout` tensor, then **every scalar as a one-element
    array**: read `n[0]`, `eps[0]`;
  - outputs: every `output` by name; **every `inout` as `<name>_out`**. MLX outputs are
    fresh buffers, so read the old value from the input `<name>` and write `<name>_out`.
- `T` is a template parameter when launch.json uses dtype "T" (`float`, `half`,
  `bfloat16_t`). Do arithmetic in float: `static_cast<float>(x[i])`, store with
  `static_cast<T>(v)`.
- Outputs start as NaN (`INIT_VALUE`, override if the algorithm needs another start).
- `ATOMIC_OUTPUTS = True` declares every output `device atomic<...>*` (for atomicAdd).
- `HEADER = """..."""` holds helper functions (placed before the kernel).
- Do not name a local variable like a param (`rows`, `cols`): params are already in scope.

## CUDA → Metal mapping

| CUDA | Metal (MLX body) |
|---|---|
| `blockIdx.x` | `threadgroup_position_in_grid.x` |
| `threadIdx.x` | `thread_position_in_threadgroup.x` |
| `blockIdx.x * blockDim.x + threadIdx.x` | `thread_position_in_grid.x` |
| `blockDim.x` / `gridDim.x` | `threads_per_threadgroup.x` / `threadgroups_per_grid.x` |
| `__shared__ float red[256];` | `threadgroup float red[256];` |
| `__syncthreads()` | `threadgroup_barrier(mem_flags::mem_threadgroup);` |
| warp shuffles (32 lanes) | `simd_sum`, `simd_max`, `simd_shuffle_xor` (SIMD width 32 on Apple GPUs), or a threadgroup tree |
| `atomicAdd(float*, v)` | `ATOMIC_OUTPUTS = True` + `atomic_fetch_add_explicit(&out_out[0], v, memory_order_relaxed)` |
| `expf`, `sqrtf`, `rsqrtf` | `metal::precise::exp`, `metal::precise::sqrt`, `metal::precise::rsqrt` |
| `fmaxf` | `metal::max` |
| `long long` | `int64_t` |
| scalar param `n` | `n[0]` |

## Precision notes

- Metal may compile with fast-math, so use **`metal::precise::`** for exp, log, sqrt
  and rsqrt. Tolerances are not loosened.
- Accumulate in float for half/bfloat16 data.

## Metal-specific bugs checklist

- [ ] `grid()` is in threads (rows × threadgroup width), not threadgroups.
- [ ] Scalars read as `name[0]`; inouts written to `name_out`, with the old value read from `name`.
- [ ] Every `threadgroup_barrier` is reached by all threads (not inside `if (tid < s)`).
- [ ] Atomic outputs: `INIT_VALUE` set to the identity (0 for sums), and an inout's
      initial value added exactly once.
- [ ] `metal::precise::` math functions.
